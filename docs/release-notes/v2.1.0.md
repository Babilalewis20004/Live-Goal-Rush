# Release 2.1.0 — Phase 7: production hardening

Previous version reported by the API: 2.0.0 (Phase 6). This release adds no football features; it makes the platform safe and observable to run.

## Features

* **Operations API** (admin only): `GET /api/v1/admin/system`, `/admin/users`, `/admin/users/{id}`, `/admin/audit-log`, `/admin/failed-jobs`, `POST /admin/failed-jobs/{id}/resolve`.
* **Audit log** of sensitive administrative actions (role changes, entitlement grants/revocations, suspensions, comment and profile moderation, article deletion, failed-job resolution, account erasure).
* **Dead-letter table** for Celery tasks that fail for good, with error class, retry count, entity and request id; repeats fold into one row.
* **Account deletion** (`DELETE /api/v1/users/me`) and **data export** (`GET /api/v1/users/me/export`), with *Profile → Your data* on web and mobile.
* **Password-reset emails** (SMTP). The link is no longer returned or logged outside development.
* **Health probes** `/health/live` and `/health/ready`; `GET /version`; `app_build_info`, dependency, pool, dead-letter and live-data-age metrics; 14 new Prometheus alerts.
* **Mobile degraded mode**: scores carry an "offline / reconnecting / last updated" banner; a cold start with no network shows the last saved board, clearly labelled; 15 s request timeout.
* **Production deployment kit**: nginx reverse proxy, production compose overlay (secrets required, Redis password/limits, nothing but nginx exposed), release overlay, rollback script, encrypted backups with restore verification, smoke test, k6 load scenarios, CI and CD workflows.

## Fixes

* Notification dispatch failed for any team with more than ~8,000 followers (bind-parameter limit) and cost 4 SQL statements per recipient (130 s for 9,076 recipients → 0.65 s); Expo pushes are now sent in batches of 100.
* A Redis outage froze the whole API (no client timeouts; metrics flushed to Redis on the event loop). Timeouts, a circuit breaker, an off-loop metrics flusher and a dedicated pub/sub connection: reads stay up and fast, the pub/sub bridge resubscribes by itself (2.3 s after Redis returned).
* PostgreSQL outage returned HTTP 500 / hung for a minute per connection attempt; now 503 + `Retry-After` within seconds and recovery ≈ 5 s after the database returns.
* `GET /competitions` and unknown-query search called the football provider on cache misses; start-up re-synced the provider on every start. Reads now serve stored data; start-up skips the sync when data is < 12 h old.
* Missing index on `refresh_tokens.replaced_by_id`: purging 18,675 expired sessions took 186 s (now 1.2 s). Three more indexes from measured queries.
* Article search no longer scans every article; unified search results are cached for 30 s (50 → 55 req/s per worker at 100 users, p50 5.4 s → 0.37 s).
* Payment webhooks: out-of-order or replayed events can no longer regress a subscription (event timestamps, monotonic periods).
* Login: constant-time for unknown emails; case-insensitive email matching; atomic rate-limit counters (no counter can lose its expiry).
* WebSocket broadcast no longer blocks on a slow client; per-address connection cap.
* Admin-only category creation checks the role before parsing the body.
* Redis `football:match:{id}:state` keys now expire (one used to remain per match forever).

## Security changes

Pillow 11.3.0 → 12.3.0 (35 advisories); Next.js 16.3.3 → 16.4.0 (critical advisories); `shadcn` moved to devDependencies; mobile `shell-quote` critical fixed. Web CSP with per-request nonce, HSTS and the standard header set; API strict
headers and 413 request-size limits; API docs/OpenAPI off in staging/production; startup configuration validation; non-root containers (web multi-stage, no package manager; API without tests or test dependencies). Full list: `docs/security/findings.md`.

## Breaking changes / upgrade notes

* **Production deployments must set secrets explicitly.** `ENVIRONMENT=production` (or `staging`) now **refuses to start** on a weak `JWT_SECRET`, `CORS_ORIGINS=*`, `ALLOWED_HOSTS=*`, the `test` billing provider, a default database password, and more. Use `.env.production.example`.
* Reset-password links are delivered by email; configure `SMTP_HOST` (and `PUBLIC_SITE_URL`) or users cannot reset passwords in deployed environments. In development the link is still returned in the response.
* `/docs`, `/redoc`, `/openapi.json` are disabled in staging/production.
* The API image no longer contains `pytest`/`fakeredis` (see `requirements-dev.txt`) and runs migrations only when `RUN_MIGRATIONS=1` (default 1 for single-container setups; set 0 for replicas and run migrations as a release step).
* Celery: task time limits are 240 s soft / 300 s hard; `task_acks_late` is on — tasks must stay idempotent (all current ones are). Unacknowledged tasks of a hard-killed worker are redelivered after 6 minutes.
* The web image now serves with `node` directly (no `npm start`) and runs as the `node` user.
* Web and mobile API clients time out after 15 s (60 s for uploads).
* `docker-compose.yml`: `api`, `worker`, `scheduler` share one image (`livepitch-api:local`); run `docker compose build api`.
* Uvicorn's proxy-header rewriting is off in the image: the application decides which `X-Forwarded-For` to trust (`TRUSTED_PROXY_CIDRS`).
* Web: team/league crests are served through Next's image optimizer from an allow-listed set of hosts (`NEXT_PUBLIC_CREST_IMAGE_HOSTS`); Vercel Analytics renders only on Vercel. Measured effect in `docs/operations/performance.md`.
* `scheduler` writes its beat schedule to `/tmp` (the image runs as a non-root user and cannot write to its working directory); the production nginx container has a writable `/var/cache/nginx` tmpfs. Both were found by booting the stack, not by tests.
* `GET /competitions` on an unseeded database with the provider unreachable returns an empty list instead of a 500.

## Known issues

* The football provider API key in git history must be rotated (S-1).
* CI/CD workflows were written and exercised command-by-command locally but have not yet run on GitHub Actions.
* No browser E2E suite exists; CSP was verified from headers and rendered HTML, not in a browser console.
* RPO is 24 h with the daily dump (no WAL archiving); RTO 3–5 min for the data tier at 300 MB (measured), larger data restores proportionally slower.
* One API instance restarts with ≈ 12 s of downtime; run two behind nginx for zero-downtime rollouts.
* Mobile toolchain advisories (Expo/Jest/Metro, build-time only) need an Expo SDK upgrade.
* One backend test (`test_match_centre_reads_populate_redis_with_status_appropriate_ttls`) failed once in a 45-minute full run and passed in four reruns (alone, in its file, with its neighbours); the cause was not established.
